How to use Archivecheck

  1. Inspect the archive

    The interface reads a fixed snapshot taken when the server starts. The station can keep recording. In Alignment, check which fields have values between archive boundaries and compare the example rows. An offset alone does not establish which record a reading belongs to. All displayed timestamps and date filters use UTC.

  2. Choose the fields

    Use Observation values to inspect a field's values and coverage. In the Fields table, check Transfer for each numeric field you want to move. In Merge records, choose a different Weather field that is populated in destination rows, for example an outdoor temperature field. No fields or aggregation methods are selected automatically.

  3. Set the destination

    Check the Archive interval and Maximum shift in seconds. Previous and Next match the preceding or following grid boundary; Nearest chooses the closest boundary. Nearest weather record matches an actual row containing the Weather field. Grid boundaries align to Unix epoch. A destination row must already exist. Equal-distance ties are conflicts; readings beyond the Maximum shift stay unchanged. Use Date range to limit the correction.

  4. Handle multiple readings

    Choose an optional Aggregation method directly in the Fields table. Choosing a method also checks Transfer for that field. Uncheck Transfer to exclude it. Without a method, multiple readings for the field cause a conflict. Mean gives each sample equal weight. Last keeps the newest reading, useful for a cumulative counter. Sum adds per-period amounts. First, Minimum and Maximum are also available. The Weather field identifies destination rows and cannot be transferred.

  5. Review the dry run

    Run dry run checks all candidates without modifying the archive. The preview shows up to 200 destination groups, with conflicts first and 20 groups per page. Use Show and Per page to filter and browse. Check timestamps, before and after values, and what remains in each source row. Missing destinations, incompatible units and differing existing destination values cause conflicts. Changed settings require a new dry run.

  6. Export the correction

    Create corrected copy first saves and verifies a permanent backup of the complete snapshot, then applies the reviewed changes to a new database and rebuilds affected scalar daily summaries in the configured station timezone. The original database stays unchanged. In the copy, transferred source values are cleared; rows with other observations remain. If conflicts exist, explicitly choose Skip blocked rows to export only ready changes.

    Download the corrected database before stopping the server. Backups remain in archivecheck-backups beside the source database, unless another backup directory was configured; the interface shows the path and download link. Create backup also works without a dry run. Save HTML or Save JSON exports the analysis and current dry run for review.
